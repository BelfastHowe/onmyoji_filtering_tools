# 阴阳师藏宝阁账号批量计算与筛选

## 使用流程

首次导入 account_data 后建立可持续追加的账号库。以后可以添加一批 JSON，也可以把新文件放入原目录后重新扫描。每次导入显示新增商品、已有商品数据更新、重复和失败的数量。按选定的规则和模式补算缺失结果，跨账号筛选和排序默认覆盖整个账号库。原始 JSON 及所在目录作为只读输入。

### 增量导入与去重

| 再次导入时遇到的情况 | 入库与计算行为 |
|---|---|
| 新的服务器与商品编号组合 | 新增商品和快照，加入当前账号库，排入所选分析任务。 |
| 同一商品、计算输入相同 | 复用快照和已有结果。文件改名、复制到另一目录、JSON 字段顺序变化，或仅请求时间、售价等元数据变化，都不会重复计算。售价与来源可以单独更新。 |
| 同一商品、御魂或其他计算输入变化 | 商品仍占一行，保存新快照，仅为它补算。当前榜采用最新快照，未完成的项目显示待算；历史批次仍可查看旧快照与结果。 |
| 同一角色换商品编号重新上架 | 两条商品都有可靠且一致的服务器和角色 ID 时，归入同一角色并保留两条上架记录，当前账号榜只显示一次。缺少可靠角色 ID 时按商品区分，昵称、价格和库存相似度不作为自动合并依据。 |

文件哈希用于快速识别相同文件；计算指纹来自规范化后所有参与分析的输入，包含御魂 UUID、未取整属性、式神等，并记录转换版本。仅对顺序无意义的集合排序后生成指纹。SQLite 对商品键、商品与计算指纹的组合，以及快照、场景、规则和参数的任务组合分别施加唯一约束。用事务登记快照并排入任务，同批重复、并行导入和中断重试均复用同一条记录。重复导入旧快照时保留当前较新的快照；可比较的采集时间优先于导入时间。

## 首批输入基线

对项目中的 30 个 JSON 做了只读检查。30 个响应均成功，按服务器和上架商品编号区分出 30 条商品记录。每条 equip.equip_detail_url 的路径都与该商品的服务器和编号一致。当前样本在已检查的角色 ID 字段中没有可用于跨上架识别的值。产品界面的「账号」在这一批里对应一条商品；同一角色换单号时不自动合并。

| 项目 | 首批实测 |
|---|---|
| 原始输入 | 188,278,178 字节；equip.equip_desc 是需要再次解码的 JSON 字符串 |
| 御魂 | inventory 共 185,262 件，每个账号 4,931–8,152 件，其中六星 +15 共 185,177 件 |
| 御魂标识与位置 | inventory 的键与 uuid 全部一致，单账号内无重复；原始位置从 1 到 6 |
| 可用属性 | 每件都有 attrs 和 rattr；前者包含展示值，后者记录属性类型与逐次系数。另有套装、品质、主属性索引和固有属性字段 |
| 式神 | heroes 共 12,573 条记录；保留式神实例、技能与佩戴关系，供还原规则时核对 |
| 评分 | 所有原始御魂都缺少 score 和 zscore。本地转换需要独立验证 |

## 架构和模块

采用 TypeScript 本地进程、SQLite、受控的 worker_threads 计算池和 Vue 本地界面。批任务由本地进程持有，关闭网页不影响计算；进程退出后可按已提交的任务续算。浏览器负责配置任务和查询结果。SQLite 随应用放在本机，运行时无需连接魔方或网易。

| 模块 | 责任 |
|---|---|
| 输入与快照 | 支持追加文件和重扫目录；按商品键、文件哈希与计算指纹识别新增、更新和重复，保留原始数据与上架链接。 |
| 格式转换 | 解码 equip_desc，将库存、式神、词条、固有属性和已有佩戴关系写入统一模型。保留原始位置、单位、系数和展示精度的映射。 |
| 游戏数据与评分 | 按版本管理式神基础面板、套装效果、成长系数、有效收益、标准分和综合分。未经验证的指标标注来源与覆盖状态。 |
| 统计引擎 | 御魂列表、御魂评分、套装雷达、满速分布、总收益次数、得分分布共用筛选和分组逻辑。任意用户组合的仓库筛选直接查询库存；常用聚合保存为可比较指标。 |
| 六件套求解器 | 接收式神、主属性、套装、面板限制、优化目标、已占御魂和计算模式，返回组合、御魂 UUID、排序值和面板。共享给一速、PVE 和阵容计算。 |
| 一速与 PVE 预览 | 登记原站每一行计算配置。保存所有一速类型和套装的结果，以及每个 PVE 预设、首领御魂选项和指标；可追溯六件套。 |
| 副本与阵容 | 登记魂土、魂王、永生之海 P1/P2、地域鬼王·极、通用阵容中的模板和变种。复现配装顺序、占用排除、队友面板依赖、伤害、治疗和达标条件。 |
| 批任务调度 | 展开账号 × 场景任务。按依赖运行、限并发、记录耗时，支持暂停、继续、重试和部分完成。默认只在一个层级并行，避免同时为每个账号再开满 CPU。 |
| 结果仓库 | 保存批次、规则版本、参数、结果状态、指标值、阵容明细和失败原因。一次事务提交一个场景，详情与摘要同时可见。 |
| 筛选与本地界面 | 批次进度页、跨账号结果表、账号详情页。筛选和排序均查已落库的数据，展示每列单位与模式，保留原链接和历史结果。 |

## 持久化模型

| 实体 | 关键字段与粒度 |
|---|---|
| 账号、商品、快照 | 商品键为 serverid + game_ordersn；有可靠角色 ID 时可将多条上架记录关联到同一账号。快照记录采集时间、文件哈希、计算指纹和转换版本。每个历史批次固定成员和快照；当前账号库可跨批次增长。 |
| 御魂、式神 | 均归属快照。御魂唯一键为 snapshot_id + uuid，同件御魂的主、副、固有属性保留可查询结构。 |
| 场景目录 | 稳定场景 ID 和可读名；区分分析项、副本、阵容、变种、速度类型、套装、PVE 预设等维度。显示名可改，历史场景 ID 保留。 |
| 规则与计算批次 | 记录数据表、转换器、算法、预设版本，及快慢模式、严格/宽容、排除条件等输入。保留版本化规则或可复现的构建产物。 |
| 任务与场景结果 | 每个批次、账号快照、场景、参数组合至多一个已提交结果。任务状态有待算、运行、完成、出错、取消；已完成的业务结论可为达标、当前模式未找到方案或不适用。 |
| 数值指标 | 每条记录引用场景结果与指标定义，如最终速度、效果命中、PVE 目标值、队伍伤害、某套五号位满速件数。指标目录规定单位、显示精度、比较方向和可用维度。数据库存数值，显示时取整。 |
| 配装明细 | 场景结果 → 方案 → 模板成员或站位 → 选用的御魂 UUID、面板、套装、检查项及其实际值/上下限。仅作挂件的成员记录模板要求；只在求解器实际分配时记录六件。 |

统计类索引按「批次、场景、指标、数值、快照」建立，阵容索引按「批次、副本、模板、结论、快照」建立。复用计算的键包含快照、场景和完整规则/参数指纹；新规则生成新结果，旧批次继续可读。未算、出错、无解分别记录；缺分保存为空，有效零值照常参与数值比较。

## 筛选与排序语义

1. 默认使用「当前账号库」与选定规则、模式，汇总各账号当前快照的匹配结果。新增账号完成对应项目后自动进入已保存的筛选和排行；也可切换至固定的历史批次。账号之间可组合多个条件；同一条方案内的速度、命中、套装要求须由同一个结果满足。不同预设通过账号快照关联。
2. 阵容条件支持「指定模板能配出」「指定模板未找到」「选中模板中任一/全部达标」「某副本达标模板数」。有未完成任务时显示“已完成数/应算数”，不将缺失结论当成失败。
3. 数值条件支持上下限和区间。允许多列排序，例如先按魂土达标模板数降序，再按招财一速降序，最后用商品键稳定打破平局。缺值默认排在有值结果之后；不同目标函数的 PVE 分数只在相同指标定义下比较。
4. 例如选「魂土指定模板达标」且「招财一速 ≥ 155」，按「指定 PVE 预设在鬼灵歌伎配置下的指标」降序。结果一行一个账号；点阵容名可查看成员和御魂，点速度或 PVE 数值可打开产生这个值的方案。
5. 对“为什么配不出来”保留可证实的信息。如某槽位无候选，记录位置和约束；只知道搜索结束时没有结果，就记录该模式未找到。若已有配装但伤害不足，显示目标血量与实际伤害。按模板计算的可配性与账号实际拥有式神/技能的可上阵性分栏，后者只在数据与规则已验证时显示。

  - Codex 环境提供 Node.js 24.22.3 和 pnpm 11.25.0。两个 Node Worker 分摊解析 30 份真实 JSON、统计库存和六星 +15 数量，用时约 0.54 秒，得到 185,262 件御魂和 185,177 件六星 +15。此用时只衡量解析与计数。全阵容配装耗时与峰值内存留待求解器阶段实测。
